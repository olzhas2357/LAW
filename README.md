# Legal information Telegram bot

Асинхронный Telegram-бот с вопросами и ответами на казахском, русском и английском языках из `legal_bot.json`, `legal_bot_ru.json` и `legal_bot_en.json`. Это справочный инструмент, а не замена юристу.

## Запуск локально

Требуется Python 3.11+ и токен бота от BotFather.

```bash
cp .env.example .env
# укажите BOT_TOKEN в .env
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m bot.main
```

Без API-ключа бот использует гибридный лексический поиск и готовые ответы из JSON. Для OpenAI embeddings и опционального RAG:

```dotenv
LLM_PROVIDER=openai
OPENAI_API_KEY=...
USE_LLM=true
```

При первом запуске язык выбирается по языку Telegram, если он поддерживается; в остальных случаях используется казахский. Язык можно сменить командой `/language` или через кнопку языка в главном меню. Выбор сохраняется для пользователя. Для каждого языка используются собственная база вопросов и поисковый индекс. Когда ИИ включён, бот отвечает по найденным записям базы на языке вопроса; если подходящих записей нет, предлагает уточнить вопрос или обратиться к юристу. При выборе готового ответа из базы доступна кнопка подробного объяснения. ИИ получает не более трёх найденных записей; он не имеет доступа к актуальным законам и может ошибаться, поэтому ответы необходимо проверять на официальных источниках. Уточняющие сообщения обрабатываются как новые вопросы, без истории диалога.

Индексы в `cache/` строятся один раз и обновляются при изменении SHA-256 исходного JSON. При сбое API или исчерпании лимита бот сообщает о недоступности ИИ и возвращается к поиску по базе. Суточные лимиты и приблизительная стоимость токенов настраиваются в `.env`; лимиты проверяются до запроса и могут быть превышены стоимостью выполняемого запроса. Для `USE_LLM=true` необходимы `LLM_PROVIDER=openai` и `OPENAI_API_KEY`. Для подключения требуется ключ OpenAI и оплачиваемый доступ к API.

Для webhook задайте `WEBHOOK_URL` (публичный HTTPS адрес) и при необходимости `WEBHOOK_SECRET`; без `WEBHOOK_URL` включается polling. `/topics`, `/emergency`, `/about`, `/feedback`, `/language`, `/delete_my_data` доступны пользователям. Команды `/stats`, `/unanswered`, `/reload`, `/broadcast` работают только для ID из `ADMIN_IDS` (список через запятую).

После ответа кнопка «Басты мәзір» позволяет вернуться к темам, экстренной помощи и справке без повторного `/start`. Меню также доступно через `/menu`, а вопрос можно отправить сразу текстом.

Голосовые сообщения распознаются через Whisper, если включены `VOICE_ENABLED=true` и OpenAI provider. Встроенный inline mode нужно отдельно активировать в настройках бота через BotFather.

## Проверки

```bash
python -m unittest discover -s tests -v
python -m scripts.build_index
python -m scripts.evaluate
```

Калибровка использует 50 вариантов вопросов из текущего JSON. Пороги `SEARCH_HIGH_THRESHOLD` и `SEARCH_LOW_THRESHOLD` можно менять без правки исходного кода.

## Конфиденциальность и ограничения

Текст сообщения очищается от типовых телефонов, ИИН, номеров карт и email перед логированием и передачей внешним API. Маскирование не гарантирует удаление всех персональных данных: при включённом OpenAI текст вопроса и найденные записи отправляются в API OpenAI. В базе хранятся маскированные вопросы, выбранные записи и обратная связь; срок хранения логов задаётся `LOG_RETENTION_DAYS`. Пользователь может удалить историю через `/delete_my_data`. Не просите у пользователей пароли, коды, карточные данные или документы. Перед эксплуатацией юридическое содержимое следует проверить по действующим официальным источникам.

При настройке production не включайте debug-логи SDK и ограничьте доступ к файлам `.env`, базы SQLite и кэша. Для нескольких процессов/реплик используйте общую очередь и полноценную серверную БД вместо SQLite.
